== Cluster Lifecycle (Cluster Lifecycle Management use case)

At a high level, Cluster Lifecycle management is about creating, upgrading, destroying, and importing clusters in a multi-cloud environment.

In the second email you received from the RHDP system, it included AWS credentials: Access Key ID, Secret Access Key, and the Base DNS Domain. To create a new OpenShift cluster in AWS, we will need these keys to create a Provider Connection.

. On the left bar, select *Credentials* and then select *Add Credential*.
+
image::acm-add-credentials.png[Adding a new credential in ACM]

. You will need to provide connection details:
* **Credential Type**: Choose Amazon Web Services and then, Amazon Web Services again.
* **Credential Name**: `aws`
* **Namespace**: `open-cluster-management`
* **Base DNS Domain**: This is in the email from the RHDP system.
. Click *NEXT*.
. **Access Key ID**: This is in the email from the RHDP system.
. **Secret Access Key**: This is in the email from the RHDP system.
. Click *NEXT* - We don't need to configure a Proxy.
. **Red Hat OpenShift pull secret**: Get from your Red Hat login.
. **SSH private and public keys(optional)**: Use an existing key pair or generate a new one. Note that the key pair needs to be in the PEM format.
. Click *NEXT*, verify the information, and add the credential.

=== Create a new OpenShift cluster in AWS

. From the *Infrastructure -> Clusters* page, select *Create Cluster*.
. Select *Amazon Web Services* and then *Standalone*.
. Select the Infrastructure provider credential: `aws`.
. **Name**: `cluster1`
. Leave the Cluster set empty for now.
. Select a Release Image, choose OCP 4.19.xx version or whatever is newest.
. Add a label of `environment=prod`. Click *NEXT*.
. Change the region according to the table below:
+
[options="header"]
|===
|If you provisioned your ACM Hub cluster in... |Select region...
|NORTH AMERICA |`us-west-1` or `us-west-2`
|EUROPE/EMEA |`eu-west-2` or `eu-west-3`
|ASIA PACIFIC |`ap-southeast-2` or `ap-northeast-2` or `ap-east-1`
|===
+
NOTE: The deployment might still fail due to a limited amount of elastic IP addresses. If so, please retry with a different availability zone.
+
image::acm-create-cluster-region.png[Selecting the AWS region for a new cluster]

. Leave everything else as default, click *NEXT* on the other screens, or select *7 - Review and create* on the menu and then click *CREATE*.
+
image::acm-create-cluster-review.png[Reviewing cluster details before creation]

In about 45 minutes, this new cluster will be ready to go!
+
image::acm-cluster-creation-progress.png[Cluster creation in progress]

=== Creating a Single Node Cluster (SNO) in AWS

In this exercise, we will create a single-node OpenShift cluster (OCP 4.13 or above required) to save time and resources.

. From the *Clusters* page, select *Create Cluster*.
. Select *Amazon Web services* and then *Standalone*.
. Select the Infrastructure provider credential: `aws`.
. **Name**: `cluster2-sno`
. Leave the ClusterSet empty for now.
. Select a Release Image, choose OCP 4.19.x version or whatever is newest.
. Add a label of `environment=qa`. Click *NEXT*.
. Select an appropriate region as described previously.
. Click on *Worker Pool 1* and change the *Node count* to `0`.
+
image::sno-worker-pool-zero.png[Setting worker node count to zero for a SNO cluster]

. Proceed with the defaults until the final step. Before creating, turn *YAML: ON*.
. Click on *"install-config"* in the YAML window pane.
. Change the master `replicas` number to `1` (it will likely be `3`).
. Double-check that the worker `replicas` is `0`.
+
[source,yaml]
----
apiVersion: v1
metadata:
  name: cluster2-sno
baseDomain: sandbox2003.opentlc.com
controlPlane:
  name: master
  hyperthreading: Enabled
  replicas: 1
platform:
  aws:
    rootVolume:
      iops: 4000
      size: 100
      type: io1
    type: m5.xlarge
compute:
- name: worker
  hyperthreading: Enabled
  replicas: 0
platform:
  aws:
# ... rest of config
----
. Click on *CREATE*.

=== Creating a Hosted Cluster with Hosted Control Planes

NOTE: Hosted Control Planes for non-Baremetal Agent Providers is a technology preview.

In this section, we will enable the feature and deploy a Hosted Cluster on AWS.

==== Setup Hosted Control Planes functionality

. Log in to the bastion machine.
. Configure your AWS credentials. For the default region name, use `us-east-2`.
+
[source,bash]
----
$ aws configure
----
. Create an S3 bucket to host OIDC discovery documents.
+
[source,bash]
----
export BUCKET_NAME=hcp-oidc-$GUID-$RANDOM
export REGION=us-east-2
# Create the S3 bucket
aws s3api create-bucket --bucket $BUCKET_NAME \
--create-bucket-configuration LocationConstraint=$REGION \
--region $REGION
# Remove public access block
aws s3api delete-public-access-block --bucket $BUCKET_NAME
# Create and apply the bucket policy
echo '{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": "*",
      "Action": [ "s3:PutObject", "s3:GetObject" ],
      "Resource": "arn:aws:s3:::${BUCKET_NAME}/*"
    }
  ]
}' | envsubst > policy.json
aws s3api put-bucket-policy --bucket $BUCKET_NAME --policy file://policy.json
----
. Create a secret in the `local-cluster` namespace for the HyperShift operator.
+
[source,bash]
----
$ oc create secret generic hypershift-operator-oidc-provider-s3-credentials \
  --from-file=credentials=$HOME/.aws/credentials \
  --from-literal bucket=$BUCKET_NAME \
  --from-literal region=us-east-2 -n local-cluster

$ oc label secret hypershift-operator-oidc-provider-s3-credentials \
  cluster.open-cluster-management.io/credentials="" \
  cluster.open-cluster-management.io/type=awss3 -n local-cluster
----

==== Deploying the Hosted Cluster

. Copy your pull secret into a file named `pull-secret` in the home directory on the bastion machine.
. Download and install the HCP CLI from the OpenShift console under *Help (?) -> Command Line Tools*.
. Create a namespace for your hosted cluster objects.
+
[source,bash]
----
$ oc new-project hcp-clusters
----
. Export the necessary environment variables.
+
[source,bash]
----
$ export CLUSTER_NAME=hcp
$ export INFRA_ID=hcp
$ export NAMESPACE=hcp-clusters
$ export BASE_DOMAIN=<<replace here with your base domain from the RHDP email>>
----
. Create the hosted cluster.
+
[source,bash]
----
hcp create cluster aws \
--role-arn <<your role info here>> \
--instance-type m5.large \
--region us-east-2 \
--auto-repair \
--generate-ssh \
--name hcp-cluster \
--infra-id infra-id-hcp \
--namespace clusters \
--base-domain $BASE_DOMAIN \
--node-pool-replicas 1 \
--pull-secret /home/lab-user/pull-secret \
--release-image quay.io/openshift-release-dev/ocp-release:4.14.0-x86_64 \
--endpoint-access=Public \
--sts-creds /home/lab-user/sts-creds.json \
--infra-availability-policy SingleReplica \
--control-plane-availability-policy SingleReplica
----
+
NOTE: The command finishes quickly, but the installation process takes around 15 minutes. You can monitor the progress from the cluster's detail page in the ACM UI.
